# אתר תמונת הבחירות — פריסה ב־Railway

האתר מוכן לחיבור למאגר GitHub ולפריסה ב־Railway. הוא נבנה עבור Node.js 22 ומעלה, ללא חבילות צד שלישי וללא מפתחות API. הקוד כולל Dockerfile והגדרת Railway.

## מה הוא עושה

- השרת מוריד את https://media26.bechirot.gov.il/files/expc.csv בהפעלה, ואז כל 15 דקות.
- הדפדפן קורא את התוצאות מהשרת בכל דקה, ובחזרה ללשונית. כפתור רענון קורא את העותק בשרת, ואינו מעמיס הורדה נוספת על הוועדה.
- מחושבים קולות כשרים, פסולים, אחוז חסימה, קולות מתחת לחסימה וחלוקת 120 מנדטים בשיטת בדר–עופר.
- כל שורת יישוב עוברת בדיקת התאמה: מצביעים = כשרים + פסולים; סכום קולות הרשימות = כשרים. נבדקים מבנה העמודות, כפילויות ומספרים.
- נתונים בלתי תקינים או הורדה שנכשלה אינם מחליפים את העותק התקין. מוצגים מועד הבדיקה האחרונה והודעת תקלה.
- אפשר להוריד תמונת PNG של הנתונים המוצגים, להציג את כל הרשימות, ולהוריד את קובץ המקור והחישוב ב־JSON.
- האתר מותאם למחשב ולטלפון.

השרת צריך להישאר פועל. אין צורך שהמחשב שלך או הדפדפן שלך יישארו פתוחים אחרי הפריסה ב־Railway.

## פריסה — פעם אחת

1. חלץ את קובץ ה־ZIP. תיקיית הפרויקט היא התיקייה המכילה את package.json ואת Dockerfile.
2. צור מאגר GitHub חדש, למשל israel-election-live, והעלה אליו את **תוכן** תיקיית הפרויקט. אפשר להשתמש ב־GitHub Desktop, ב־Git, או בהעלאת קבצים בממשק GitHub. אל תעלה את ה־ZIP עצמו.
3. ב־Railway בחר New Project → Deploy from GitHub repo, וחבר את המאגר. Railway יזהה את Dockerfile. אם הפרויקט נמצא בתת־תיקייה במאגר, הגדר אותה כ־Root Directory בשירות.
4. הוסף Volume לשירות עם Mount Path של /data. ב־Variables הגדר DATA_DIR=/data. כך העותק האחרון נשמר גם בפריסה מחדש או בהפעלה מחדש. בלי Volume האתר עדיין פועל, אך לאחר פריסה חדשה יתחיל מקובץ הגיבוי עד להורדה מוצלחת.
5. ב־Settings → Networking / Public Networking בחר Generate Domain. אם נשאלת על Target Port, השתמש בפורט שהשרת מדווח בלוג, או הגדר PORT=3000 והשתמש ב־3000.
6. השאר את השירות פעיל תמיד: כבה Serverless / App Sleeping אם הופעל, והשאר Replica יחידה. מנגנון הבדיקה המחזורי פועל בתוך השירות.
7. פתח את הכתובת הציבורית. ודא שמופיע "מחובר למקור" עם זמן בדיקה עדכני, ובדוק שהמספרים הגיוניים. בדוק גם /healthz (שרת תקין) ו־/api/results (כולל מצב הורדת הנתונים). בדיקת healthz מאשרת שהיישום פועל, ואינה מאשרת שהמקור הרשמי זמין.
8. להחלפת קוד, שמות או הסכמים, עדכן את המאגר. פריסת GitHub אוטומטית תטען את השינוי. עדכוני הקולות עצמם אינם דורשים commit או פריסה.

העלויות והשימוש הם בהתאם לתוכנית Railway שלך; לא בוצעה רכישה או פריסה בחשבונך במסגרת ההכנה.

## הגדרות

| משתנה | ברירת מחדל | משמעות |
| --- | --- | --- |
| DATA_DIR | cache בתוך הפרויקט | הגדר /data כשמחובר Volume |
| POLL_SECONDS | 900 | מרווח בדיקות מקור, לפחות 60 שניות |
| PORT | 3000 | Railway יכול לספק אותו אוטומטית |
| SOURCE_URL | הכתובת הרשמית לעיל | שינוי מקור במקרה של שינוי כתובת; חייב HTTPS |
| OFFLINE | לא מוגדר | ערך 1 מפסיק הורדות לצורך בדיקה מקומית בלבד |

אין להפעיל OFFLINE בפריסה המתעדכנת. אין כאן ממשק ניהול ציבורי או נקודת קצה להעלאת נתונים.

## הסכמי עודפים ושמות הרשימות

config.json מכיל את השמות, השיוך לגושים והסכמי העודפים:

- הליכוד + הציונות הדתית / זהות
- ש״ס + יהדות התורה
- ישר! + הדמוקרטים
- ביחד + ישראל ביתנו
- הרשימה המשותפת + רע״ם

הזוגות מבוססים על [דיווח גלובס](https://www.globes.co.il/news/article.aspx?did=1001561042) שנמצא בעת ההכנה. לא אומתו מול הודעה רשמית של ועדת הבחירות. לכן agreementsVerified נשאר false והאתר והתמונה מסמנים את המגבלה. יש לאמת את הזוגות מול הודעת הוועדה לפני הסתמכות על המנדטים כתוצאה רשמית. שמות הרשימות ומיפוי אותיות הפתק עבור הרשימות המופיעות בתמונת הייחוס מבוססים על הנתונים שסופקו. לשאר הרשימות מוצגות אותיות הפתק; ניתן להשלים שמות ב־config.json.

החלוקה לגושים היא בחירה תצוגתית על פי התמונה שסופקה, ולא סיווג רשמי של ועדת הבחירות. רשימה חדשה שעוברת חסימה ואין לה שיוך מוגדר תופיע בגוש "ללא שיוך לגוש".

אם התקבלה אסמכתה רשמית, עדכן את agreementsSource, את הזוגות במידת הצורך ואת agreementsVerified ל־true. טקסט המתודולוגיה הוא חלק מהאתר; יש להתאים גם את ההערה שמתחת למפת המושבים ב־public/index.html.

## שיטת החישוב

הסף הוא 13/400 מהקולות הכשרים. מספר הקולות השלם המזערי למעבר הוא עיגול כלפי מעלה. פסולים אינם כלולים במכנה.

תחילה מקצים לכל רשימה שעברה את הסף את החלק השלם של קולותיה חלקי המודד הכללי (סך קולות הרשימות הזכאיות / 120). את יתרת המושבים מקצים לפי המודד קולות/(מושבים+1), תוך איחוד רשימות עם הסכם פעיל. בסיום מחשבים מודד פנימי לכל זוג לפי סך מושביו, ומחלקים בין שתי הרשימות. ההשוואות נעשות במספרים שלמים כדי למנוע שגיאות עיגול. במקרה של שוויון המחייב הגרלה, החישוב מסומן כלא זמין ולא נבחר זוכה שרירותי.

הפער המוצג מתחת לחסימה הוא מול הסף הנוכחי בהנחת סך קולות קבוע. לשורת "יתר הרשימות" אין פער משותף, משום שהחסימה נבחנת לכל רשימה בנפרד.

מספר היישובים בקובץ אינו שיעור השלמת ספירת הקלפיות. זמן בדיקה מוצלחת הוא זמן הורדת הקובץ או אימותו, ולא בהכרח הזמן שבו הוועדה שינתה אותו. זמן שינוי המקור מוצג בנפרד כששרת המקור מוסר אותו.

[הסבר שיטת בדר–עופר באתר הכנסת](https://main.knesset.gov.il/About/Lexicon/pages/seats.aspx)

## בדיקה מקומית

התקן Node.js 22 ומעלה, פתח מסוף בתיקיית הפרויקט והרץ:

~~~sh
npm test
npm start
~~~

פתח http://localhost:3000. אין צורך ב־npm install, משום שאין תלויות חיצוניות.

הבדיקות מכסות את נתוני הייחוס, כל מנדטי הרשימות בתמונה, סף החסימה, הסכמים לא פעילים, שוויון, השוואה לחישוב עצמאי, קובץ פגום, עדכון מקור, תגובת HTTP 304, שמירה ושחזור לאחר הפעלה מחדש. בסביבת Windows מוגבלת אפשר להגדיר TEST_TMPDIR לתיקייה זמנית שבה מותר לכתוב.

## אימות שבוצע בהכנה

- הקובץ המצורף: 3,758,580 כשרים; 16,881 פסולים; 200,996 מתחת לחסימה; מנדטי הגושים 54–48–18.
- הורדה חיה מוצלחת ב־28.10.2026 בשעה 11:43 לפי שעון ישראל: 4,008,086 כשרים; 17,963 פסולים; 212,929 מתחת לחסימה; מנדטי הגושים 54–47–19, תחת ההסכמים המוגדרים.
- נבדקו דפדפן במחשב ובטלפון, הרחבת 27 הרשימות, המתודולוגיה והורדת PNG.

נתוני הבדיקה הם תיעוד נקודתי; האתר יחשב מחדש לאחר כל הורדה. לא נבדקה עדיין גישה למקור מתוך תשתית Railway שלך, ולא נבנתה תמונת Docker בסביבה זו. אם המקור יחסום את כתובת ה־IP של השרת, תופיע תקלה והעותק האחרון יישמר. יש לבדוק את החיבור לאחר הפריסה.
